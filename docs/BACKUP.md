# Восстановительный резерв

Реализован формат **hourly-v2**: все исходные пакеты и управляющие события сохраняются, полные рассчитанные параметры — в десятисекундных временных корзинах. Каждый час с данными начинается новый файл; активация новой калибровки также начинает отдельный файл с причиной. Новые профили используют hourly-v2 и Zstd 1 («Сбалансированное»). Прежний полный журнал v1 доступен как режим совместимости; старые файлы не удаляются.

## Что записывается

| Данные | Когда |
|---|---|
| Сырые значения, время, качество, источник/сессия и версия карты | Каждый подтверждённый пакет, без прореживания |
| Полный рассчитанный результат | Первый поступивший результат в каждой новой 10-секундной корзине и первый после начала файла |
| Проверка промежуточного результата | Ссылка на исходный пакет и CRC32 точного исходного результата |
| Карты, активации, ручные значения, настройки ядра, открытия/закрытия источников и прочие события ядра | Сразу при получении из журнала |
| Шапка: действующая карта, источники/каналы, версии и начальное состояние расчётов | В начале каждого файла |

Запись проверки занимает существенно меньше места, чем повтор всех параметров. При восстановлении KERN пересчитывает промежуточный результат по сохранённым входам и контексту, затем сверяет CRC. Несовпадение останавливает импорт; подмены расчёта текущей калибровкой нет. Для ссылок на пакеты вне текущего файла предусмотрена копия нужного исходного события. Поддерживаются существующие linear-v1 и graph-v1, включая окна скорости. Совместимая реализация этих алгоритмов необходима; CRC — контроль повреждений/воспроизводимости, не криптографическая подпись.

Если интерпретатор остановлен, сырые данные продолжают сохраняться. Новые рассчитанные значения не выдумываются: отсутствие результатов видно по их времени. Резерв не берёт прореженные точки с графического экрана. Библиотека пользовательских наборов, настройки линии, оформление и собственные настройки резерва пока не входят в журнал ядра; это не копия всей установки.

## Папки, границы и причина

```text
backup/hourly-v2/
  2026-10-25/
    14-00-00_hour-r41-e00000000000000123456.kbk
    14-25-00_calibration-r42-e00000000000000124001.kbk
    15-00-00_hour-r42-e00000000000000125001.kbk
```

Суффикс e — исходная позиция события: предотвращает перезапись при повторе времени и позволяет восстановить порядок при коррекции часов. Границы используют время приёма/активации из ядра, а не дату выполнения исторического экспорта. Час без новых событий не создаёт пустой периодический файл. Настройка `utc_offset_minutes` записывается в шапку; для новых профилей сейчас +240 (UTC+04:00). Это фиксированный сдвиг, без автоматического перехода на летнее время; редактора часового пояса пока нет.

Новый файл начинается при **подтверждённой активации** версии карты. В шапке находятся полная новая карта, прежняя/новая ревизии, точное время и причина, например: «В 14:25 изменена калибровка: Вес на крюке. Версия 41 → 42». Названия изменившихся параметров определяются автоматически; учётные записи/достоверная личность оператора этим срезом не добавлены. Для старых активаций без собственного времени используется последняя известная временная отметка. Следующая часовая граница сохраняется.

Начальное состояние содержит карты, текущие входы, параметры и контекст окон. Поэтому отдельный час можно восстановить без вычисления всех прежних часов. Это не возвращает отсчёты до выбранного интервала: в отчёте `baseline_position` показывает начальную границу. Для всей истории передавайте корень коллекции; пропущенный промежуточный файл или другая ветка состояния дают отказ. Порядок определяется позициями событий, а не сортировкой времени в имени. Для восстановления после длительного отставания интерпретатора предпочтителен корень коллекции: повторный экспорт одного восстановленного интервала со ссылками на raw до его baseline не гарантируется без более ранних файлов.

## Настройки и размер

Единственная кнопка ⋮ → «Восстановительный резерв»: состав, папка, сжатие, фактический файл и общий размер текущей коллекции. «Выбрать…» открывает отдельное системное окно; его закрытие/зависание не блокирует ядро. «Сохранить» проверяет revision, «Отмена» отбрасывает черновик. Смена состава завершает процесс писателя; управляемый плагин перезапускается надзором. Для отдельно запущенного CLI-писателя его нужно запустить снова. Изменения папки/уровня применяются в рабочем цикле; новая папка догоняет доступную историю, недоступная оставляет действующий писатель на прежнем пути.

| Режим | Сжатие блоков |
|---|---|
| Без сжатия | Исходные блоки |
| Быстрое · слабый ПК | Zstd −3, один поток; кандидат для J4125 |
| Сбалансированное | Zstd 1, один поток; стандарт новых профилей |
| Компактное | Zstd 3, один поток |

Во внешней папке создаётся `kern-<profile_id>/hourly-v2`. Старые JSONL/KBK v1 и коллекции прежних папок сохраняются отдельно; их размер не включается в счётчик текущей коллекции. Трей считает закрытые файлы по счётчику манифеста и размеры активного файла/хвоста по метаданным, без рекурсивного обхода раз в пять секунд. Для внешнего тома отдельно измеряется свободное место. Частоты CSV и общего завершения всех вторичных писателей это не меняет.

До реализации исследована выборка 3000 событий за 330,305 с: после отбора 34 десятисекундных снимков при сохранении 1500 raw-пакетов Zstd 1 давал оценку 16,4–18,2 МБ/сут без новых шапок/состояния/проверочных записей. Предварительный бюджет 20–30 МБ/сут (0,6–0,9 ГБ/30 суток) остаётся ориентиром для примерно 30 каналов с частотой около 1 Гц и 30 параметров. Это не месячная приёмка и не гарантированный лимит. Новая реализация дополнительно хранит проверки результатов и состояние; её фактический объём зависит от данных/версий карт/частоты. Превышение бюджета не разрешает молча отбрасывать входы. Ресурсная приёмка J4125 впереди.

## Запись, хвост и сбой

Сжатие выполняется независимыми блоками, целевой размер 256 КиБ. Пока блок собирается, записи подтверждаются `sync_all` в соседнем служебном `.tail` на том же выбранном носителе. Сначала синхронизируется сжатый блок `.kbk`, затем очищается хвост. Обрыв между этими действиями может оставить дубликат; reader проверяет его совпадение и применяет один раз. Перезапуск читает начальный снимок и только текущий файл, а не всю многомесячную историю.

Закрытый файл получает END2 с позицией/контрольной суммой состояния и становится самостоятельным; его пустой хвост можно не переносить. **Для активного файла необходимы оба файла: `.kbk` и `.tail`.** При отсутствии обязательного хвоста импорт отказывается считать копию полной. Копируйте закрытые часы либо остановите писатель и перенесите всю коллекцию со служебными файлами. Один носитель для базы и резерва не защищает от отказа этого носителя.

Недописанный последний кадр исключается. Перед продолжением писатель сохраняет его точные байты в отдельный ASCII-файл `.bin`. Полностью повреждённый кадр, неверная карта/последовательность/контрольная сумма не маскируются усечением. Пустой незарегистрированный заголовок после прерывания создания сохраняется отдельно и создаётся заново; незарегистрированный файл с данными требует явного восстановления. Общий drain при остановке всего KERN ещё не реализован: основная история может опережать резерв, который догонит её после запуска.

## Проверка и восстановление

```powershell
kern-core.exe backup-info --input PATH_TO_HOURLY_ROOT_OR_DAY_OR_FILE
kern-core.exe restore --input PATH_TO_HOURLY_ROOT_OR_DAY_OR_FILE --profile NEW_PROFILE_PATH
kern-core.exe check --profile NEW_PROFILE_PATH
```

`backup-info` показывает причины, карты, границы, число полных снимков/проверок и целостность. `restore` также читает прежние JSONL/KBK v1 при передаче файла. Выходная папка должна быть новой. Ошибка оставляет `import-incomplete`, запрещающий открыть частичный профиль. Восстановленная база хранит проверенный начальный снимок в отдельной таблице redb и продолжает исходную нумерацию событий; `dump` сначала показывает baseline, затем события выбранного интервала. Первоначальные события заново не придумываются.

Проверки: `cargo test --workspace --locked`, `python tools/validate_hourly_backup.py`; смена часа/суток/карт, полное совпадение восстановленных событий и окна скорости, обрыв/дубликат хвоста, CRC, независимый импорт файла, запуск восстановленного профиля и повторный резерв. Совместимость v1 — `python tools/validate_prototype.py` и `python tools/validate_backup_settings.py`. [Отчёт](validation/hourly-backup-20261025.json). Windows10/macOS, слабые ПК, месяц записи, полный fault injection и power-loss ещё не приняты.

## Технический контракт

Магия v2 — `KERNBKP2`. Кадры HDR2 (начальное состояние), DAT2 (записи), END2 (закрытие) имеют заголовок 32 байта little-endian: tag[4], codec u8 (0 исходный / 1 Zstd), level i8, reserved[2]=0, plain_len u32, stored_len u32, CRC32 исходного payload u32, last_sequence u64, CRC32 первых 28 байт u32. DAT2 содержит JSON-строки event/result/snapshot с исходной sequence. HDR2 ≤16 МиБ, DAT2 ≤1 МиБ, сохранённый payload ≤2×лимит; окна декодера ≤16/2 МиБ соответственно. Карты/контекст дополнительно проверяются ядром. Источник/линия настроек не берутся через прямые ссылки на память другого плагина.

Чтение каталога ограничено 4096 записями на уровень и 100000 файлами, пути манифеста ограничены двумя компонентами внутри коллекции. Raw-cache — 64 события; при более старой ссылке нужный raw встраивается в проверочную запись. Начальный снимок восстановленного профиля передаётся писателю по ограниченным страницам ArchiveBaseline (48 КиБ, общий предел 16 МиБ, CRC), без выдачи полного состояния в обычном snapshot. Формат состояния пока привязан к совместимой версии KERN. [Zstd](https://github.com/facebook/zstd), [лицензии](dependencies.json).

Рабочий перенос 25.10.2026: прежний JSONL 1 733 897 441 байт сохранён; новая копия накопленной истории — 31 576 492 байта, 51 файл. Проверены 723 140 промежуточных результатов пересчётом/CRC; 16 165 полных снимков защищены CRC блоков. Это объём накопленной истории, не замер суток. Исходный приём продолжился, новый резерв догнал ядро; карта/линия сохранены.

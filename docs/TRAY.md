# Трей и состояние записи

Срез 25.10.2026, Windows. Значок KERN находится в системном трее возле часов; Windows может поместить его под стрелку скрытых значков. Наведение показывает состояние основной записи, свободное место на томе профиля и суммарный размер активных файлов данных. Правый клик раскрывает размеры базы, CSV и резерва отдельно и состояние процессов писателей. Левый клик открывает окно состояния ядра. Крестик этого окна и «Свернуть в трей» скрывают окно, сохраняя процесс, heartbeat и значок. Остановка KERN — отдельная команда с подтверждением.

| Цвет | Значение |
|---|---|
| Зелёный | В статусе ядра нет ошибки диска, поступают подтверждённые сырые пакеты; видимых предупреждений нет |
| Янтарный | Свободно менее 4 ГиБ, размер неизвестен, настроенный CSV/резерв остановлен, интерпретатор отстаёт или новых подтверждений нет дольше допустимого времени |
| Красный | Ядро сообщает ошибку основной записи; успешная пульсация отключена |
| Синий | Ожидание входных данных / первой записи |
| Серый | Приём остановлен, нет связи или статус ядра устарел; причина указана в подсказке |

Яркий импульс запускается только при увеличении подтверждённого счётчика raw_batches в том же запуске ядра. Первое чтение старых счётчиков и смена boot не дают фиктивного импульса. Продолжительность 400 мс, проверка кадра раз в 250 мс; нет графического цикла 60 FPS. Десять иконок (пять цветов × два уровня яркости) создаются один раз и освобождаются при выходе. Изменение значка/подсказки отправляется только при изменении состояния; после TaskbarCreated значок регистрируется заново. Открытое меню не держит заимствование App и не блокирует heartbeat.

Зелёный импульс подтверждает основную запись ядра, а не fsync вторичных файлов. «CSV работает»/«Резерв работает» означают состояние процесса. Позиция резерва после fsync теперь доступна в его настройках; отдельной позиции CSV пока нет; закрытие общего drain остаётся отдельной задачей. Время снимка статуса сохраняется до доставки в UI, поэтому старый ответ из очереди не становится свежим. После 3,5 с без свежего статуса индикатор серый. Отставание интерпретатора проверяется относительно предыдущей входной границы, чтобы нормальная небольшая задержка непрерывного потока не давала постоянного предупреждения.

## Какие размеры показываются

Свободное место — байты, доступные вызывающему пользователю на томе папки профиля, через GetDiskFreeSpaceExW. Это учитывает квоту пользователя. «Файлы данных» — сумма логических размеров активной базы measurements.redb (либо сегментов journal/segment-*.kjn), exports/parameters.csv и фактического файла резерва из backup-status.json (при отсутствии статуса — из backup-settings.json). Учитывается служебное пространство базы и повторное хранение данных в разных файлах; это не размер одних числовых отсчётов и не количество выделенных блоков файловой системы. Посторонние файлы, старые контрольные копии, настройки и сохранённые повреждённые хвосты в сумму не входят. Ошибка измерения показывается как «н/д», не как ноль.

Измеритель работает в отдельном потоке раз в пять секунд, очередь — один снимок; обхода всего профиля и чтения содержимого измерений нет. Для прежнего KJN просматривается только каталог сегментов, максимум 4096 записей. Задержка дискового запроса не блокирует IPC-heartbeat; через 15 с без нового измерения размеры становятся неизвестными. Порог 4 ГиБ — предупреждение оболочки, он не останавливает приём и не меняет правила disk ack ядра. Частоты отсчётов пока не настраиваются. Папка и сжатие резерва — [BACKUP](BACKUP.md). Для внешней папки отдельно измеряется доступное место её тома; неизвестное значение, менее 4 ГиБ либо ошибка писателя дают янтарное предупреждение. Сумма учитывает активный файл резерва, без старых файлов прежних папок.

Проверки/точные бинарники: [CORE_VALIDATION](CORE_VALIDATION.md). Поведение системных API: [Shell_NotifyIcon](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shell_notifyiconw), [GetDiskFreeSpaceEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw). Ресурсная приёмка J4125, Windows10/macOS, 24–72 часа и power-loss пока впереди.

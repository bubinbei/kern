# Параметры и интерпретатор

Срез 24.10.2026: каталог 81 определения, семь встроенных наборов и пользовательские версии; рабочие способы получения — калиброванный канал, значение оператора, граф готовых расчётов. Экран остаётся в общем host charts, алгоритмы выполняет отдельный Rust-процесс processor. Каталог принадлежит исходникам processor (`parameter-library.json`) и встроен в текущий host; универсального SDK вкладок/подключаемых каталогов пока нет. Полный последующий план — [PARAMETER_PRESETS_PLAN](PARAMETER_PRESETS_PLAN.md).

## Наборы и рабочие настройки

«Добавить…» открывает каталог с группами/поиском и зависимостями. «Варианты настроек…» показывает список слева и полный состав справа: единица, способ, нужные входы, изменение и готовность. Видны секции и точные количества. Начальный режим при каждом открытии — «Добавить недостающие», сохраняющий прежние определения/привязки/точки. Обновление состава и замена списка явные; замена требует отметки. Выбор меняет только черновик; «Применить» сохраняет версию ядром, processor подтверждает активацию. Отмена не меняет рабочий набор.

Встроенные группы: базовая технология; глубина/нагрузка/скорости; три насоса; раствор; пять ёмкостей; газ C1–C6; объединённая технология и раствор. Большой набор содержит 59 определений, каталог дополнительно содержит ёмкости до 16. Это определения, не готовые полевые калибровки. Источник без настройки — unassigned, выключен, точки пустые. Провода IM2480 назначают такой канал пунктиром, обработка включается после калибровки. Расчётные/ручные параметры не являются входными контактами IM2480.

Пользовательский набор сохраняется из черновика, в `profile/parameter-presets/<ASCII-ID>.json`: формат kern-parameter-preset-v1, название/описание, версия, секции, карта. Встроенное не перезаписывается. Повтор имени создаёт новую неизменяемую версию с новым ID. По умолчанию исключаются привязки/калибровки и введённые значения; включить их можно отдельными отметками. Измерения, ключи и накопленная история не входят. Импорт сначала проверяется и показывается; сохранение в список — отдельное действие. Удаление набора не меняет регистрацию. Пользовательские файлы переживают restart host, но как библиотека шаблонов пока не входят в JSONL-резерв; активные карты входят.

Пределы: до 32 пользовательских версий, файл до 60 КиБ, название до 128 байт, описание до 1024 байт. Рабочая карта — до 128 определений и 48 КиБ одновременно; неизвестные поля моделей отвергаются, частичного применения нет. История карт остаётся ограниченной 256 ревизиями. Импорт не устанавливает исполняемые плагины.

## Способы получения

Без provider действует прежняя калибровка канала. `provider.kind=manual` содержит конечное value или null («не задано»); изменение фиксируется новой картой и действует на её границе активации, не на произвольно выбранной исторической дате. `provider.kind=calculation` задаёт входные ID, operation и max_age_ms. Имена/цвета не участвуют в ссылках; единица существующего ID исторически неизменна.

Поддержаны версии linear-v1 и graph-v1. Новый редактор выбирает graph-v1 при появлении provider. Старые карты/события читаются и сериализуются без новых пустых полей: CRC ранее записанного JSON сохраняется. Новые graph-события требуют новой согласованной сборки ядра/processor/писателей.

| Операция | Явный смысл |
|---|---|
| sum / difference | Сумма 1–16 входов / первый минус второй; одинаковые единицы |
| ratio | Первый / второй × коэффициент; одинаковые единицы входов, результат % или ед.; нулевой знаменатель — ошибка |
| scale | Вход × коэффициент + смещение, явно объявленная единица результата |
| pump_flow | Ходы/мин × литры за ход × коэффициент подачи / 60 → л/с |
| lookup | Кусочно-линейная таблица 2–32 точки; вне таблицы нет значения |
| weight_on_bit | Свободный вес − вес на крюке; если высота над забоем превышает заданную границу — 0. Нужны все три входа, свободный вес > 0 |
| rate | Приращение входа в метрах за полное окно 1–300 с; результат м/с либо м/ч, необязательное ограничение отрицательного приращения |

Нагрузка — ограниченная явно выбранная модель; правильность свободного веса, высоты и полевых условий проверяет оператор. Начальные глубины в каталоге — ручные значения: автоматический учёт глубины по ДОЛ/клиньям/операциям ещё не реализован. Временная скорость углубления не заменяет механическую скорость на интервале проходки с распознаванием времени бурения. Средние, максимумы и периоды записи остаются отдельными будущими правилами писателя. Произвольного языка выражений/eval нет.

## Время, качество и восстановление

Граф проверяется на неизвестные входы, циклы, единицы и коэффициенты; порядок подготавливается один раз для версии. В рабочем цикле поддерживаются последние подтверждённые входы разных источников. Возраст определяется записанным временем приёма; допустимо 100–3600000 мс, по умолчанию 5 с в каталоге. Это явная политика удержания последнего значения в пределах возраста, а не обещание синхронности датчиков. Источник/сессия не подменяются.

Для скорости сохраняются опорные точки входа по секундным корзинам, с линейной интерполяцией на левой границе окна. Не более восьми скоростей и 302 опорных точек на окно. Пока не накоплено полное окно — null/warming_up. Пропуск больше допустимого возраста, новая ревизия или смена сессии зависимого источника сбрасывают окно. Регресс календарного времени помечается clock_regression и начинает новое накопление; расчёт использует записанное календарное время, не синхронизирует часы оборудования. Защита свежести входов ядра по монотонному времени сохранена.

Выход содержит value/quality и для graph-v1 reason/input_time_ms. Причины различают отсутствие/старение входов, необходимость настройки, прогрев, выход за таблицу, деление на ноль и неконечный результат. Ошибка не становится числовым 0. Snapshot дополнительно проверяет качество/сессии исходных каналов и отставание; переобработка старого входа не делает его свежим. Для графа это ещё не универсальная трассировка каждого входного raw-event ID.

`processing_context {position}` возвращает согласованный контекст только для подтверждённой позиции processor. Он строится из принятых parameters_stored, не из будущих сырых отсчётов. После Durable интерпретатор продвигает свою копию; ядро проверяет стандартный результат по тому же контракту и только после commit продвигает авторитетную проекцию. Одинаковый повтор результата не продвигает окно повторно. Restart и восстановление из JSONL восстанавливают контекст из подтверждённых событий, без полной повторной интерпретации всех raw. Старые карты запрашиваются через calibration_at.

Реализация стандартных дешёвых операций общая для проверки ядра и processor. Это текущая ограниченная проверка результата, не загрузчик произвольных тяжёлых алгоритмов в ядро. Численная приёмка дополнительно использует независимые эталоны. Контекст/окна ограничены; snapshot мемоизирует качество зависимостей, несколько параметров одного результата разделяют его метаданные в памяти. Каталог не перечитывается и формулы не разбираются в каждом цикле.

Приём сырых данных и писатели продолжают жить независимо от окна настройки. Активация новой карты намеренно заново собирает её входы/окна; перенос состояния через изменение схемы не выполняется. UI/API остаются локальными с отдельным ключом. Права отдельных алгоритмов, полноценные checkpoint сторонних stateful-плагинов и сетевой режим — последующие этапы.

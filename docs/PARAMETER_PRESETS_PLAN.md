# Каталог параметров, наборы и расчёты

Статус: предложение следующего этапа, 24.10.2026. Каталог, наборы и граф расчётов ещё не реализованы. В текущем прототипе есть редактор отдельных параметров и карты linear-v1: один сырой канал, кусочно-линейная калибровка, до 32 параметров. Импорт карты не является каталогом наборов. Этот документ описывает самостоятельные требования KERN; готовые профили и чужие реализации не импортируются.

## Три понятия для оператора

| Понятие | Что содержит | Действие |
|---|---|---|
| Каталог параметров | Определения: название, единица, смысл, допустимые способы получения, зависимости и необходимые алгоритмы | «Добавить параметр» с поиском/группами; можно создать собственный |
| Набор настроек | Именованный, версионированный список параметров с выбранными способами получения и настройками; необязательные секции калибровок, привязок, экранов, записи | Предпросмотр, добавить в текущую конфигурацию, сохранить свой набор |
| Рабочая конфигурация | Конкретные экземпляры параметров, входы, проверенные калибровки, расчёты и записанные оператором исходные данные | Черновик → проверка → сохранение версии ядром → активация |

Выбор набора заполняет черновик. Он не запускает COM, не устанавливает исполняемый код и не меняет рабочую конфигурацию автоматически. Изменение рабочей конфигурации не переписывает исходный набор. Пользователь может дополнить набор любым параметром каталога или собственным определением.

## Окно выбора набора

Слева — список и поиск: встроенные/мои, назначение, название, версия. Справа — полный состав выбранного набора, сгруппированный по назначению. В каждой строке: параметр, единица, способ получения, необходимые входы, состояние. Доступны фильтры «все», «с датчика», «расчётные», «ввод оператора», «нужно настроить».

Ниже — отдельный перечень включённых секций: параметры, алгоритмы/настройки расчётов, калибровки, привязки оборудования, экраны, правила записи. Отсутствующая секция явно отмечается. Перед применением показываются точные количества и изменения: добавится/обновится/сохранится/будет отключено, конфликты и недостающие зависимости. Числа получаются из реального содержимого набора.

Действие по умолчанию — «Добавить недостающие»: существующие привязки и калибровки сохраняются. Обновление выбранных строк и полная замена — явные режимы со сравнением. Конфликтующие определения одного устойчивого ID разрешаются выбором, совпадение названий не означает совпадение параметров. Удаление набора не удаляет рабочие параметры или историю. Смена набора не стирает записанные измерения.

Начальные направления наборов: базовая технология, глубина и СПО, насосы, ёмкости и раствор, газовый контроль, диагностика. Полный рабочий набор собирается из нескольких таких групп, без дублирования общих зависимостей. Точный состав определяется отдельно; этот список не обещает уже реализованных расчётов. Если нужного алгоритма/плагина нет, строка видна как недоступная и не выдаёт числовое значение.

## Способ получения значения

| Способ | Настройка и поведение |
|---|---|
| Канал источника | Экземпляр источника + постоянный канал + карта калибровки; код/В для соответствующего аналога |
| Расчёт | Идентификатор/версия алгоритма, входные параметры, коэффициенты, временное или глубинное окно, условия применимости |
| Ввод оператора | Значение, единица, время/граница действия и событие изменения в ядре; это не фиктивный отсчёт датчика |

Один физический смысл может иметь альтернативные способы получения. Например, расход на входе — датчик расхода либо расчёт по насосам. Активен один явно выбранный способ; автоматическая подмена при отказе требует отдельной политики и события. Название/цвет можно менять без смены устойчивого ID. Повторяемые объекты, например ёмкости, получают отдельные ID экземпляров.

Каталог группируется по задаче (технология, глубина/скорости, насосы, раствор/ёмкости, газ, пользовательские), а способ получения — отдельное поле. Поэтому расчётные и измеренные величины удобно видеть рядом. В таблице настроек нужны колонки «Способ», «Входы» и «Готовность»; кнопка для расчётного параметра открывает его зависимости и настройки, для датчика — калибровку.

## Зависимости и примеры

```mermaid
flowchart LR
    Raw[Сырые каналы ядра] --> Cal[Калибровки интерпретатора]
    Cal --> Graph[Граф расчётов интерпретатора]
    Manual[Записанные действия оператора] --> Graph
    Cal --> Params[Таблица параметров ядра]
    Graph --> Params
    Params --> View[Графики и писатели]
```

Это логические стадии одного расчётного тракта. Отдельная обязательная таблица между калибровкой и формулами не требуется. Несколько алгоритмов могут работать в одном Rust-процессе интерпретатора; отдельный процесс на каждый параметр не нужен.

- Нагрузка на долото: для первого согласуемого варианта — свободный вес колонны минус текущий вес на крюке, с явным событием задания свободного веса и условиями применимости. Это предварительная модель, не универсальная полевая методика. Нужны правила обновления эталона, учёта состояния инструмента и качества входов.
- Скорости: отдельно определять скорость перемещения, усреднённую скорость углубления и скорость на заданном интервале проходки. Нужны разные входы, окна и правила учёта времени бурения/пауз; одного названия «скорость» недостаточно.
- Расход по насосам: ходы каждого насоса, объём за ход и коэффициент подачи; единицы и коэффициенты явные. Нельзя одновременно складывать этот расчёт с датчиком того же расхода без специального определения результата.
- Объём ёмкости: уровень и собственная градуировочная таблица ёмкости; общий/активный объём — список участвующих ёмкостей. Добавление ёмкости не должно незаметно менять состав суммы.

При добавлении расчёта UI показывает дерево зависимостей и предлагает добавить отсутствующие определения. Добавление определения не создаёт отсутствующий датчик и не подставляет произвольную калибровку. Например: «Нагрузка: не задан свободный вес», «Скорость: нужна глубина и история». Состояния должны различать отсутствие входов, настройку, прогрев окна, устаревание и ошибку расчёта. Отсутствие данных, ошибка формулы и деление на ноль не превращаются в 0.

## Граница ядра и плагинов

Каталоги/алгоритмы предоставляют плагины; экран настройки редактирует черновики. Ядро владеет рабочими определениями, неизменяемыми версиями конфигурации и границами активации. Шаблон ссылается на ID и совместимую версию определения; при применении полное выбранное определение фиксируется в рабочей версии. Обновление каталога не меняет текущую регистрацию. Удаление необходимого алгоритма запрещается для активного расчёта либо переводит его в явное состояние недоступности; история остаётся читаемой.

Исполняет расчёты Rust-интерпретатор. Граф проверяется на отсутствующие входы, циклы, совместимость единиц, версии и лимиты. Обычные формулы не ссылаются на прошлое значение неявно; накопление/осреднение — специальные алгоритмы с состоянием. На первом этапе нужны проверенные готовые алгоритмы; затем ограниченный редактор выражений с предпросмотром и ограничением сложности, без eval произвольного кода.

Порядок расчёта определяется зависимостями. Входы разных источников согласуются по явной временной политике и допустимому возрасту, а не по порядку чтения таблицы. Граф проверяется/подготавливается при активации версии; в каждом цикле пересчитывается затронутая часть, без повторного разбора формул и загрузки всего каталога. Окна истории ограничены. Все результаты несут версию конфигурации/алгоритма, происхождение и качество; расчёт по старой истории не становится свежим. Долгие/ошибочные расчёты не блокируют raw.

Для алгоритмов с памятью нужны подтверждённые checkpoint/позиция и правила восстановления окна. Параметры скважины, свободный вес, начальная глубина и другие изменения, влияющие на результат, должны попасть в журнал как входы расчёта. Резерв получает рабочие версии, события и необходимые checkpoint через ядро. Доступность версии исполняемого алгоритма при replay проверяется отдельно: одного JSON с формулой недостаточно для любого восстановления. Этот контракт расширяет нынешний stateless linear-v1 и требует отдельной реализации.

## Сохранение своих наборов

«Сохранить как набор…»: название, описание, версия, группы, перечень секций и предпросмотр файла. По умолчанию сохранять определения/расчёты без конкретных COM, рабочих привязок, начальных глубин, свободного веса и измеренных калибровок. Перенос проверенных привязок/калибровок — отдельные явно выбранные секции с указанием происхождения и необходимости проверки на другом стенде. Измерения, секреты и состояние накопителей в набор не входят.

План формата — декларативный JSON с версией схемы и ASCII-ID/путями, например `parameter-presets/drilling-basic/preset.json`; русские названия допустимы внутри. Встроенные наборы защищены от случайной перезаписи, редактирование создаёт пользовательскую копию в профиле. Сохранение добавляет её в список, импорт проверяет схему/размер/версии и показывает содержимое; отсутствие плагина не запускает его установку. Набор не является исполняемым плагином. Это будущая структура, текущий загрузчик её не поддерживает.

## Порядок внедрения и приёмка

1. Каталог и библиотека наборов, предпросмотр/сравнение, добавление и сохранение своих наборов. Сначала только реально поддерживаемые виды; недоступные расчёты явно обозначены. Рабочий профиль не менять при открытии/отмене.
2. Версионированная модель способов получения/зависимостей и записанных исходных данных оператора. Совместимость старых карт, рабочих журналов и replay обязательна. Лимит 32 расширить согласованно в контракте/IPC/хранилище/GUI после измерения бюджета; большой набор не должен частично применяться из-за переполнения.
3. Простые расчёты без памяти: разность/сумма, расход по насосам, объём по таблице. Независимые численные эталоны и проверка качества.
4. Глубина/нагрузка/скорости после согласования полевых условий, сбросов/переходов и checkpoint. Принудительный restart/backlog должны дать тот же результат, что непрерывный расчёт.

Обязательные сценарии: точное совпадение preview и применяемого состава; add/merge без потери калибровок; конфликты ID/версий; добавление зависимости без дублирования; пользовательский набор после restart/export/import; отсутствие плагина; цикл/единицы/деление на ноль; разновременные/устаревшие входы; согласованная активация во время приёма; восстановление из резерва с версиями и ручными событиями. На слабом ПК измерить время обновления/память при реальном числе активных параметров; размер каталога не должен определять стоимость каждого цикла расчёта.

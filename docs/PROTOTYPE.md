# Первый сквозной прототип KERN

Реализован опытный тракт Windows: **IM2480 → redb → отдельный интерпретатор → параметры → uPlot, CSV и резерв**. Это рабочий срез до альфы, не промышленная приёмка. Старый комплект KJN и его профили не мигрируются и не переписываются. Результаты испытаний и точные бинарники привязываются к [CORE_VALIDATION](CORE_VALIDATION.md).

## Запуск

Локальный комплект: `dist/Kern-Prototype-0.1.0`. Откройте `Start-Kern.cmd` внутри него либо `Start-Prototype.cmd` в корне проекта. Запускаются ядро с отдельной нативной оболочкой и пакеты `im2480`, `processor`, `charts`, `csv`, `backup`. Повторный запуск подключается к работающему профилю. COM и модули задаются в локальном `plugins/im2480/config.json`; этот файл не входит в Git.

Окно графиков пока использует установленный Edge или Chrome в режиме приложения, с отдельным каталогом браузерного профиля. Интернет и CDN не нужны: uPlot/JS/CSS встроены в исполняемый файл host. Это временный способ доставки первого веб экрана, а не окончательный выбор встроенного WebView. Нативное служебное окно остаётся отдельным. Удалённого доступа нет: host слушает только случайный порт `127.0.0.1`, выдаёт отдельный ключ представления и не передаёт браузеру IPC-токен ядра.

Закрытие окна графиков не останавливает регистрацию. Полная остановка — `Stop-Kern.cmd` либо команда остановки ядра в нативной оболочке. `Status.cmd` показывает состояние. `Check-Data.cmd` проверяет журнал **после остановки**. Ошибки компонентов сохраняются в `data/prototype/logs/*-console.log`, старт ядра — в `core-console.log` профиля.

Сборка/упаковка разработчиком:

```powershell
cargo build --workspace --release --locked
python tools/package_prototype.py --config PATH_TO_LOCAL_IM2480_CONFIG
```

Упаковщик сохраняет существующий локальный COM-конфиг и не трогает `data`. Новый профиль запускается с `--storage redb`; базовый CLI без этого аргумента сохраняет прежний backend KJN. Несовпадение backend с профилем отвергается. Новые профили/имена файлов — ASCII.

## Калибровки

Вкладка «Калибровки» задаёт ID/название параметра, источник, номер канала в резерве источника, единицу, точки `raw = значение`, цвет и пределы шкалы. Изменения сохраняются общей неизменяемой ревизией карты. Интерпретатор проверяет/загружает её и подтверждает активацию; экран отдельно показывает сохранённую и активную ревизии.

Начальные шесть карт из `calibration.example.json` — **только тестовые шкалы для демонстрации**, с соответствующим названием. Они не являются калибровкой датчиков. Параметры получают каналы 0–5 первого настроенного слота IM2480; при другом слоте источник/канал нужно изменить. Остальные модули также записываются сырыми и могут быть назначены новым параметрам.

Алгоритм карты явно обозначен `linear-v1`: кусочно-линейная интерполяция между 2–32 возрастающими точками raw. Например, 1000=0 и 8800=1 дают 4900=0,5. За пределами карты результат по умолчанию bad/без значения; линейное продолжение включается отдельно. Missing/bad вход не превращается в нуль. Целые сырые значения остаются точными в архиве; значения вне точного целочисленного диапазона f64 не округляются в этом интерпретаторе, а дают bad. Осреднения, формул между несколькими входами и stateful-расчётов пока нет.

Ядро присваивает принятому сырому пакету активную ревизию. Поздний результат сверяется с исходным пакетом и исторической картой; старая сессия, пропуск позиции и неверный линейный результат отвергаются. Первый прототип дополнительно проверяет численный результат стандартного алгоритма в ядре. Новый алгоритм потребует отдельного контракта/проверки, а не подмены смысла `linear-v1`. Пересчёт старого входа не обновляет его свежесть. Latest-параметры показывают отставание/качество отдельно от живости процесса.

## Графики и управление

Вертикальные дорожки uPlot показывают выбранный интервал; сетка и время привязаны к одним временным координатам. Мелкая сетка — чередование слабых фоновых заливок. Колонки меняют ширину перетаскиванием границы. Колесо/ползунок/стрелки листают сохранённую историю; «Сейчас» возвращает последний принятый результат. Архив не очищается при смене интервала. Запрос ограничен сутками; если бюджет чтения исчерпан, экран явно предлагает уменьшить интервал.

Один ЛКМ на поле не добавляет кривую. ПКМ открывает небольшое окно добавления кривой в дорожку. Двойной ЛКМ возле отсчёта (до 10 CSS px) ставит флажок; ближайшая кривая имеет приоритет, при разнице расстояний менее 3 px предлагается выбор. Двойной ЛКМ на подписи удаляет флажок. Флажки компактны, без крестика, с контурной точкой и линией; это локальные аннотации браузерного профиля, **ещё не серверные записи/часть резерва**. При отображении агрегированной истории выбор сейчас привязан к сохранённым экранным отсчётам; точное уточнение произвольного места между ними — следующий срез.

Плашка параметров переключается между развёрнутым видом, строкой и скрытым видом. Курсор показывает значения цветом кривых, прерывистую линию только в своей дорожке и контурные маркеры. Частота обновления экрана около 1 Гц; перерисовка скрытой страницы отключена. Кэш графиков не заменяет архив. Кнопка «Автошкалы» подбирает видимый диапазон по данным экрана, не меняя калибровки и архив; её можно отключить для фиксированных пределов карты. Вкладка «Плагины» управляет заранее установленными компонентами; загрузчика пакетов через браузер здесь нет.

## Сохранность и файлы

| Файл профиля `data/prototype` | Содержание |
|---|---|
| `measurements.redb` | Авторитетные события, исходные значения, версии/активации карт, результаты, позиции и индексы |
| `exports/parameters.csv` | Открытый рабочий CSV: время, вход/результат, источник/сессия, ревизия, ID, значение и качество |
| `backup/events.jsonl` | Независимый несжатый журнал событий с порядком и CRC, достаточный для восстановления этого среза |

redb использует `Durability::Immediate`, отдельный writer и кэш 16 МиБ. Прототип прекращает приём с явной ошибкой при достижении порога файла базы 4 ГиБ; это грубая защита, не готовые квоты/ротация. Размер страницы/резервирования может пересечь порог одной транзакцией. Запись на физически отказавшем диске не гарантируется.

CSV и backup — отдельные процессы с собственными контрольными метками. Строки CSV `#commit,...` служебные; обычный читатель должен их пропускать. Текущий Windows-писатель держит эксклюзивный файл; открывайте CSV внешней программой после остановки этого плагина. Незавершённый хвост при запуске сохраняется отдельно перед усечением собственного файла до подтверждённой границы. Ошибка CRC полного блока не скрывается усечением. Периоды обычного/быстрого потока пока не реализованы: CSV пишет каждый полученный результат, включая quality. Резерв в том же профиле не защищает от отказа носителя.

Управляемые `processor`, `csv`, `backup` после аварии получают ограниченный restart (до 3 запусков/60с, затем safe mode). Интерпретатор посылает pulse из рабочего цикла; истечение lease 15с или отсутствие прогресса при backlog более 20с приводит к завершению только своего процесса и восстановлению позиции. Приём продолжается. Явная остановка плагина отключает его автоматический restart. Автовосстановления физически отключённого COM и произвольных сторонних плагинов пока нет. Карты ограничены 256 ревизиями, параметры — 32, источники — прежними резервами; это явные пределы прототипа.

Восстановление из резерва не требует исходной базы, но требует совместимой версии KERN/алгоритма:

```powershell
kern-core.exe restore --input PATH_TO_BACKUP_EVENTS_JSONL --profile NEW_PROFILE_PATH
kern-core.exe check --profile NEW_PROFILE_PATH
```

Выходная папка должна быть новой. Ошибка импорта оставляет `import-incomplete`: сервер не открывает частично восстановленный профиль. Исходный резерв не меняется. `dump --profile PATH` выдаёт проверенные события JSONL для независимого сравнения. Полный offline-импорт прежнего KJN в redb пока не реализован.

## Границы приёмки

Проверяются синтетические значения независимым Python-эталоном, исторические карты при backlog, повтор пакета, отдельные писатели, forced kill/restart, восстановление из резерва, рабочий эмулятор через виртуальный COM и настоящий браузер. Dev-проверка браузера использует Playwright под `target/browser-tools`, в поставку он не входит. Результаты: [CORE_VALIDATION](CORE_VALIDATION.md).

Windows10, слабый ноутбук, macOS, реальная RS-485/датчики, GPU, 24–72ч, power-loss, длительные квоты и все сценарии полного C2–C6 ещё не приняты. Сетевая выдача/учётные записи/офисное управление остаются планом [NETWORK_PLAN](NETWORK_PLAN.md). Следующие задачи — оптимизация длительного replay/истории, измерения на слабом стенде и последующие контракты; не объявлять весь roadmap выполненным по этому прототипу.

CSV/backup асинхронны и восстанавливают свой подтверждённый префикс. Полная остановка сейчас не гарантирует догон всех последних результатов вторичными файлами: они догоняются при следующем запуске из redb. Сохранность основной подтверждённой истории и актуальность резервной копии — разные состояния; окончательный протокол drain/позиций вторичных писателей ещё впереди.

Единица существующего ID параметра неизменна: для другой единицы создайте новый ID. Это не позволяет подписать старые значения в тоннах новой единицей «кг» без пересчёта истории. Имена/цвет/шкала и точки калибровки могут меняться по обычному протоколу ревизий.

Редактор «Настройка параметров» использует отдельный черновик: выбор строки, редактирование свойств и окно точек с таблицей/графиком. «Применить точки» меняет черновик, «Применить» сохраняет новую карту с проверкой expected_revision; отмена не меняет ядро. Смена карты извне не перезаписывает открытый редактор. Точки можно переносить в собственном JSON kern-calibration-points-v1 с проверкой единицы параметра.

Для зарегистрированных аналоговых А1–А3 IM2480 принята **шкала отображения** 0–12 В ↔ 0–65535: U=raw×12/65535. Обратный ввод сохраняется как raw=U×65535/12; дробные координаты точек не округляются до целого АЦП. Это соглашение UI, не подтверждённая метрологическая характеристика физического прибора; полевая проверка/метаданные диапазона источника впереди. Частоты отображаются в Гц, счётчики — исходными кодами; неизвестным каналам вольты не присваиваются. Переключение В/код и отмена не переписывают точки; интерпретатор, raw-журнал и прежние карты не изменены. Прокрутка использует локальный кэш и анимацию до 30 кадров/с только при движении, запросы истории ограничены отдельно.

Окно точек: ЛКМ и перетаскивание фона перемещают вид; +/− меняют масштаб обеих осей, «Вписать» показывает все точки. Вид сохраняется при редактировании точек до закрытия окна или смены единицы сигнала; координаты/версии карт от этих действий не меняются. Перерисовки объединяются по кадру только при взаимодействии; canvas не пересоздаётся при каждом движении. Сетка привязана к кратным значениям осей, поэтому линии и подписи перемещаются вместе с кривой; шаг 1/2/2,5/5×10ⁿ выбирается по масштабу, точность подписей следует за шагом.

# Этапы и приёмка

Целевой план; текущее выполнение и границы — [CORE_VALIDATION](CORE_VALIDATION.md). Первый raw-срез C0–C1 и выбранные C2-проверки реализованы на Windows11, целевая Windows10 ещё не принята. Каждое расширение повторяет общую отказную проверку. Сначала изолированный синтетический профиль; реальные приборы и рабочие данные не трогать без отдельной задачи.

Утверждён следующий порядок внедрения redb/uPlot: **R1 storage/raw → R2 offline-импорт → R3 карты/интерпретатор/replay → R4 API/uPlot-прототип → R5 писатели/backup → R6 слабый стенд и интеграция**. Это уточнение C2–C6, не замена уже пройденных проверок. Следующий рабочий срез — R1; текущая сборка ещё использует KJNv1 без uPlot/redb. Контракты трёх наборов и приёмка каждого шага: [STORAGE_CHARTS_PLAN](STORAGE_CHARTS_PLAN.md).

| Этап | Результат | Приёмка |
|---|---|---|
| C0 | Минимальный Rust workspace, контракт сообщений, детерминированный тестовый источник | Windows 10 x64: сборка/запуск, эталон ID/значений/качества |
| C1 | Headless-ядро, реестр, bounded-приём, сырой журнал и CLI статуса | Без UI/интерпретатора входы сохраняются и читаются после restart |
| C2 | Отказы диска/процессов/IPC, повреждение хвоста, переполнение | Подтверждённый префикс совпадает с независимым эталоном; потери/разрывы явные, память ограничена |
| C3 | Стандартный интерпретатор, карты и границы активации, replay | Падение/живой heartbeat с зависшим worker; старые/новые карты при backlog; результат без дублей/перестановок |
| C4 | Собственный рабочий формат и CSV, обычный/быстрый потоки | Независимое чтение схем/периодов/наборов/значений; restart и догоняющая запись |
| C5 | Первый источник оборудования, затем другой тип и несколько экземпляров | Один COM на экземпляр, резерв адресов, отказ одного источника не останавливает другие |
| C6 | Минимальная оболочка, затем графики/виджеты | Отказ/закрытие UI не останавливает сбор; hidden/idle без лишней работы |

Обязательные проверки: snapshot/subscribe без потери события; stale revision/повтор request ID; падения между save/load/activate; поздние ответы старой сессии; усечение/CRC/ошибка sync; поток во время replay; три одинаковых значения с разной свежестью; расширение 18+20→24+20 каналов без перенумерации.

Нагрузку измерять отдельно для ядра, плагинов и оболочки: CPU, GPU, RAM, диск, очереди и задержка. Сценарии: idle, live, 24 часа истории, прокрутка, скрытое/свёрнутое окно, отказ и догоняющая обработка. Успешная сборка не подтверждает скорость или устойчивость. Численные бюджеты принять после C0–C2.

Ручные стенды пользователя: слабый Windows-ноутбук Intel «4125» (точную модель уточнить при испытании); Mac 2012 под macOS — поздний этап. Первая обязательная платформа Windows 10 x64; macOS пока не поддержана. Планировать 24–72 часа непрерывной записи после коротких отказных тестов. Запуск на этих стендах ещё не проводился.

Выбранный C6-срез выполнен раньше интерпретатора: нативная обязательная оболочка, меню/настройки и ручное управление пакетами; её падение/зависание не останавливает сырой журнал. Далее завершать C2 и развивать контракты C3. Отдельное будущее направление W1 — операторская веб среда/конструктор виджетов без программирования; ответственные плагины остаются Rust. Порядок и критерии выбора движка — [PLUGINS](PLUGINS.md). Подробное руководство ядра запрошено владельцем и ведётся сейчас; помощь по меняющемуся UI и новая косметика отложены.

Первый выбранный C5-срез: плагин **im2480**, настраиваемые COM/адреса/постоянные слоты, шесть сырых каналов на модуль, 17 отказных проверок через виртуальную пару и короткая проверка существующего эмулятора. Это не закрывает физическую/длительную приёмку C5. Контракт: [IM2480](IM2480.md).
